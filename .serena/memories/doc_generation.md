# Document Generation Pipeline Memory

The document generation pipeline converts structured JSON cases into compiled `.docx` files using `docxtpl` and legacy Hindi font encodings.

- **Sale Deed**: `SDTemplateProcessor` in [processor.py](file:///c:/Users/aksha/Documents/RM%20Generator/RM-Maker/RM-Maker-MAIN/modules/sd/processor.py).

## Unicode to Legacy Font Conversion
- **Problem**: Microsoft Word templates in use rely on legacy non-Unicode Hindi fonts (specifically `DevLys 010` / `Kruti Dev`).
- **Solution**: The web interface captures clean Unicode Hindi (Segoe UI/Mangal) to avoid rendering and input issues in browsers.
- **Conversion**: During document generation, `_convert_context_to_legacy(data)` recursively traverses the template context and calls `Unicode_to_KrutiDev(text)` from [helpers.py](file:///c:/Users/aksha/Documents/RM%20Generator/RM-Maker/RM-Maker-MAIN/utils/helpers.py) for all Hindi fields, transforming Unicode chars into the matching DevLys ascii sequence before writing to docx.

## Template Rendering Flow
1. Load case data JSON.
2. Initialize `DocxTemplate(template_path)`.
3. Process and format boundary/narrative text blocks.
4. Coerce dates to ordinals (`format_date_to_ordinal_english`).
5. Convert all Hindi Unicode fields to DevLys.
6. Render the document using `self.doc.render(context)`.
7. Save the compiled output to `cases/`.

## Highlighting & AI Markers
- **AI Highlighting**: If `highlight_ai` is enabled, variables extracted/generated by AI are marked with a visual highlight color in the document.
- **Missing Fields**: If a field is missing, it is populated with a placeholder or highlighted in red/yellow using custom RichText runs.
