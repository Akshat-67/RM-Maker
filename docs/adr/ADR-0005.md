# ADR-0005: Removal of Graphify

## Status
Accepted

## Date
19-07-2026

## Context
Early iterations of the development guidelines integrated "Graphify"—a script that converted the codebase, AST symbols, and markdown files into a static repository knowledge graph saved inside `graphify-out/`.
This tool was added to help AI agents understand the repository structure. However, in practice, it introduced major issues:
1. **Size Concerns**: The generated graph database and associated markdown files was huge, inflating the workspace size.
2. **Maintenance Overhead**: It required running an update script (`graphify update .`) after every code change, slowing down development.
3. **Redundancy**: The knowledge graph duplicated the code structure and documentation already present in the workspace, adding no additional benefit for modern LLMs with large context windows.
4. **Tool Failures**: Graphify scripts often failed to parse syntax in newer Python environments or required external packages that were difficult to maintain.

## Decision
Graphify is **completely removed** from the RM-Maker development lifecycle and documentation:
- Delete all local Graphify rules and workflow configs.
- Strip references to Graphify from the `Definition of Done` and development guidelines.
- Replace the graph database with structured, modular documentation under `/docs` and long-term project memories managed via Serena.

## Alternatives Considered
- **Keeping Graphify in Background**: Rejected. The developer would still need to run update scripts, leading to maintenance overhead.
- **Replacing with Light Graph Generator**: Rejected. Modern coding agents do not require an intermediate JSON graph file to understand relationships when clean, cross-linked markdown files and language server capabilities (like Serena) are available.

## Consequences
- **Positive**: Simplified, cleaner workspace. Faster test runs and development iterations. Clearer onboarding guidelines.
- **Negative/Neutral**: Developers must manually update documentation and Serena memories when making significant architectural changes.

## Future Considerations
By relying on standard documentation `/docs/` and Serena memories, the project remains highly accessible to any modern coding agent or human developer without requiring custom graph parsing tools.
