# ADR-0007: Incremental Refactoring Policy

## Status
Accepted

## Date
19-07-2026

## Context
Legal document automation platforms handle highly specific workflows containing edge cases (e.g. particular spelling rules, regional property boundaries, name/relation conventions, and specific template requirements). Over time, the codebase accumulates fixes for these edge cases.
A common pitfall for new engineers or AI agents is attempting to rewrite entire modules to make the code look more elegant or conform to a specific style. These rewrites often cause regressions, breaking compatibility with older session files or breaking edge-case handling.

## Decision
All modifications, features, and fixes in this repository must follow an **Incremental and Surgical Refactoring Policy**:
- **Surgical Edits**: Prefer modifying target functions or replacing localized code segments rather than rewriting entire files or pipelines.
- **Backward Compatibility**: Preserve existing schema keys and JSON formats. Stored case files represent API contracts.
- **Respect Historical Context**: Do not remove helper logic or conditional parsing simply because it looks redundant without verifying why it was added (e.g., verifying if it handles legacy OCR issues, hyphenated addresses, or specific transliteration details).
- **Regression Testing**: Every refactor or bug fix must be accompanied by an automated test case that validates the change against original behaviors.

## Alternatives Considered
- **Periodic Green-field Overhauls**: Rejected. Rewriting modules from scratch introduces high regression rates and requires extensive manual validation, which is unacceptable for a production legal system.
- **Strict Linting Enforcement**: Rejected. While style consistency is useful, forcing automatic refactoring rules across the codebase can break delicate template string parsing.

## Consequences
- **Positive**: Low regression rate and highly stable production builds. Existing case histories remain fully loadable.
- **Negative/Neutral**: The codebase may retain legacy patterns or less elegant blocks to preserve compatibility.

## Future Considerations
By enforcing incremental refactoring, the project remains stable and maintainable over the long term, enabling multiple engineers and AI assistants to contribute safely.
