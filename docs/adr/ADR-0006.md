# ADR-0006: Runtime Data is Not Source Code

## Status
Accepted

## Date
19-07-2026

## Context
When running, RM-Maker generates various files:
- Individual case folders (`cases/case_<id>/`).
- Uploaded PDFs, JPEGs, and text files.
- Compiled deeds, crops, and debug reports.
- Temp caches, SQLite files (`cases.db`), and intermediate JSON metrics.
Historically, some tools or configurations treated these runtime directories as part of the application context, causing them to be indexed, analyzed, or committed to git. This caused major performance and security issues.

## Decision
All generated cases, uploads, outputs, and intermediate logs are classified strictly as **Runtime Data** and must never be treated as application source code or committed to git.
- **Strict Ignored Rules**: These directories (`cases/`, `uploads/`, `outputs/`, `instance/`, `scratch/`) are ignored globally in `.gitignore`.
- **Decoupled Architecture**: No application logic, module imports, or template compilation steps may depend on files residing inside these runtime directories, except for loading session data (`session.json`) and serving static media files.
- **Test Sandbox Isolation**: Running test suites must mock or isolate the directories using temporary paths (e.g. `tmp_path` in pytest) to ensure test runs do not read or corrupt production case histories.

## Alternatives Considered
- **Committing Sample Cases**: Rejected. Storing sample cases in the main repository exposes sensitive KYC data (Aadhaars, loan amounts, PANs) and increases repository size. Instead, use mocked payloads within the `/tests` folder.
- **Storing Case Databases in Cloud**: Rejected. High local latency and offline requirements necessitate local file system storage for cases.

## Consequences
- **Positive**: Clean, lightweight source repository. Minimal risk of committing private client data. Fast testing loops and container packaging.
- **Negative/Neutral**: Developers must manually configure `.env` paths and ensure folders exist when running the app for the first time.

## Future Considerations
This strict decoupling ensures that the entire cases directory can be migrated to a dedicated database or external cloud storage without changing the core application logic.
